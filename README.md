# AgriCore Command Center

Prairie Crest Agricultural Cooperative farm operations app: equipment, field jobs, service reports, and operational analytics.

Local-first stack: **React (Vite) + MUI**, **FastAPI**, **PostgreSQL**, **AWS S3** for report files.

## Prerequisites

- Python 3.10+
- Node.js 20+ and npm
- Docker Desktop (local PostgreSQL)
- AWS IAM keys and a **private** S3 bucket (needed starting Slice 4)

## Quick start

```bash
chmod +x bin/setup.sh bin/seed.sh
./bin/setup.sh
```

`setup.sh` creates `backend/.venv`, installs Python and npm packages, starts Postgres via Docker Compose, and writes local `.env` files (including a generated `JWT_SECRET_KEY`).

### Run the API

```bash
cd backend
source .venv/bin/activate
uvicorn app.main:app --reload --app-dir .
```

Health check: [http://localhost:8000/health](http://localhost:8000/health)  
OpenAPI: [http://localhost:8000/docs](http://localhost:8000/docs)

### Run the UI

```bash
cd frontend
npm run dev
```

UI: [http://localhost:5173](http://localhost:5173)

### Migrate and seed

```bash
docker compose up -d postgres
./bin/seed.sh
```

`seed.sh` runs `alembic upgrade head` and loads Prairie Crest mock data (`python -m app.seed --reset`). Re-running `--reset` replaces farms, users, equipment, jobs, and audit logs.

## Environment variables

Copy from examples (`backend/.env.example`, `frontend/.env.example`). `bin/setup.sh` does this for you.

### Backend (`backend/.env`)

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | SQLAlchemy URL for Docker Postgres (`agricore` / `agricore` / `agricore` on **port 5433** — host 5432 is often already taken) |
| `JWT_SECRET_KEY` | Generated by setup; do not commit |
| `JWT_ALGORITHM` | `HS256` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Default `480` |
| `CORS_ORIGINS` | Comma-separated origins; default `http://localhost:5173,http://127.0.0.1:5173` |
| `AWS_ACCESS_KEY_ID` | IAM user (Slice 4+) |
| `AWS_SECRET_ACCESS_KEY` | IAM secret (Slice 4+) |
| `AWS_REGION` | e.g. `us-east-1` |
| `AWS_S3_BUCKET` | Private bucket name |
| `BOOTSTRAP_ADMIN_EMAIL` | Default `admin@agricore.local` |
| `BOOTSTRAP_ADMIN_PASSWORD` | Default `ChangeMeAdmin!` |
| `BOOTSTRAP_ADMIN_NAME` | Display name for the first admin |

IAM needs `s3:PutObject`, `s3:GetObject`, and `s3:DeleteObject` on the bucket. Keep the bucket private; the API will issue presigned download URLs.

### Frontend (`frontend/.env`)

| Variable | Purpose |
| --- | --- |
| `VITE_API_BASE_URL` | REST prefix. Default `/api/v1` (Vite proxies to FastAPI). Absolute `http://localhost:8000/api/v1` also works if CORS allows the UI origin |
| `VITE_API_HEALTH_URL` | Health probe, default `/health` |

## API (current)

| Method | Path | Who | Notes |
| --- | --- | --- | --- |
| `GET` | `/health` | public | Liveness |
| `POST` | `/api/v1/auth/login` | public | `{ "email", "password" }` → JWT + user |
| `GET` | `/api/v1/auth/me` | any role | Current user |
| `GET` | `/api/v1/auth/admin-check` | admin | RBAC smoke test |
| `GET/POST` | `/api/v1/farms` | GET admin+auditor; POST admin | List / create |
| `GET/PATCH/DELETE` | `/api/v1/farms/{id}` | GET admin+auditor; write admin | |
| `GET/POST` | `/api/v1/users` | GET admin+auditor; POST admin | Admin creates accounts (no public signup) |
| `GET/PATCH/DELETE` | `/api/v1/users/{id}` | GET admin+auditor; write admin | |
| `GET/POST` | `/api/v1/equipment` | GET all roles (field hand: assigned only); POST admin | |
| `GET/PATCH/DELETE` | `/api/v1/equipment/{id}` | GET scoped; write admin | |
| `GET/POST` | `/api/v1/field-jobs` | GET all roles (field hand: own jobs); POST admin | |
| `GET/PATCH/DELETE` | `/api/v1/field-jobs/{id}` | PATCH: admin any fields; field hand **status only** on own jobs; DELETE admin | |
| `GET` | `/api/v1/audit-logs?q=` | admin+auditor | Search `action`, `entity_type`, `details` |
| `GET` | `/api/v1/analytics/low-fuel` | any role | Active units (`Idle` / `In-Use`) with `fuel_level < 20` |
| `GET` | `/api/v1/analytics/co-location` | any role | Assigned units whose operator `farm_id` ≠ `facility_id` |
| `GET` | `/api/v1/analytics/reliability` | any role | `Completed` / `Failed` job counts by equipment model |
| `GET` | `/api/v1/analytics/maintenance-flags` | any role | Farms where maintenance units are **> 30%** of the fleet |
| `GET` | `/api/v1/analytics/reporting-lines?supervisor_id=` | any role | Distinct field hands on that supervisor’s farms with `Pending` / `In-Progress` jobs |
| `POST` | `/api/v1/field-jobs/{id}/reports` | admin; field hand on **own** jobs | Multipart `file` + optional `notes`. Images, `.txt`, `.pdf`. Max 10 MB. Stores object in private S3 |
| `GET` | `/api/v1/field-jobs/{id}/reports` | same visibility as the job | List reports; `file_url` is a 1-hour presigned GET |
| `GET` | `/api/v1/field-jobs/{id}/reports/{report_id}` | same visibility as the job | One report with a fresh presigned GET |

Writes append an `audit_logs` row (`actor_id`, `action`, `entity_type`, `entity_id`, `details`). Unique email/serial conflicts return `409`. Errors are JSON `{ "detail": ... }`. Request validation returns `422` with `detail` plus `errors`.

```bash
TOKEN=$(curl -sS -X POST http://localhost:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@agricore.local","password":"ChangeMeAdmin!"}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')

curl -sS http://localhost:8000/api/v1/auth/me -H "Authorization: Bearer $TOKEN"
```

Report files stay in a private bucket; clients download via the presigned `file_url`. OpenAPI tags are grouped at `/docs`.

## Roles

- **Farm Operations Admin** — full CRUD (JWT `role=admin`)
- **Field Hand** — assigned equipment, own job status (`field_hand`); co-op analytics GET; service reports on own jobs
- **Auditor** — GET-only on farms/users/equipment/jobs/reports plus audit log search (`auditor`)

Dependencies: `get_current_user`, `require_roles(...)` in `backend/app/api/deps.py`.

## Live deploy (CloudFront + EC2 + RDS)

HTTPS on CloudFront cannot call `http://ec2-...:8000` (mixed content). Deploy scripts put the API on EC2, proxy `/api/*` and `/health` through CloudFront, and upload the UI to S3.

1. Put `agricore-key.pem` at `~/.ssh/agricore-key.pem` (or set `AGRICORE_SSH_KEY`).
2. Confirm `backend/.env` has `RDS_PASSWORD`, `JWT_SECRET_KEY`, AWS keys, and `AWS_S3_BUCKET` (reports bucket).
3. IAM for those keys must allow S3 on `frontend-agricore`, CloudFront updates, and the reports bucket.
4. Your current IP must be allowed on the EC2 security group for SSH (port 22).

First deploy (creates RDS tables and demo users):

```bash
chmod +x bin/deploy.sh
./bin/deploy.sh --seed
```

Later deploys (keep data):

```bash
./bin/deploy.sh
```

Live URL: https://d23sefiwm7ezpn.cloudfront.net

CloudFront origin changes often take 5–15 minutes. Demo logins are the same as local after `--seed`.

`deploy/aws.env` holds public hostnames and IDs. Production secrets are written to gitignored `backend/.env.production` by `bin/make-production-env.py`.
